\chapter{Protocole experimental et demarche scientifique}

\section{Comment j'ai structure ma demarche}
Le professeur a insiste sur la demarche scientifique; j'ai donc structure mes essais comme suit:
\begin{enumerate}
  \item je pose une hypothese (ex: l'occlusion doit mieux simuler les cas reels de points manquants);
  \item je fais varier un facteur principal a la fois;
  \item je garde des constantes (dataset, architecture de reference, batch size, metriques);
  \item j'analyse a la fois les chiffres et les visuels (courbes, matrices de confusion, nuages augmentes);
  \item je ne retiens une decision que si elle reste defendable sur plusieurs runs.
\end{enumerate}

\section{Donnees et constantes de travail}
Dans mon notebook final, j'utilise:
\begin{itemize}
  \item ModelNet10\_PLY (10 classes, 1024 points/objet),
  \item split: train 3193 / val 798 / test 908,
  \item PointNetFull comme modele de reference pour les campagnes d'augmentation,
  \item scheduler actif et early stopping pilote sur la validation,
  \item test execute en fin de run seulement.
\end{itemize}

\section{Metriques suivies}
\begin{itemize}
  \item \texttt{best\_val\_acc}: meilleure accuracy validation pendant l'entrainement;
  \item \texttt{final\_val\_acc}: accuracy validation au dernier epoch execute;
  \item \texttt{best\_eval\_acc}: score du checkpoint selectionne;
  \item \texttt{final test accuracy}: mesure finale sur test en fin de run.
\end{itemize}

\noindent\textbf{Analyse.} Cette separation m'evite de confondre une bonne dynamique de validation avec une vraie generalisation sur test.
